# Тихо — личный планер

Русский mobile-first планер: React 19, Vite, Zustand/localStorage, один Cloudflare Worker со статикой, D1 и Workers AI. Интерфейс работает без аккаунта и офлайн; Telegram связывает устройства и принимает текст/голос. Шрифт Golos Text поставляется с приложением.

> **Перед деплоем обязательно замените `database_id = "REPLACE_WITH_D1_ID"` в `wrangler.toml` на UUID вашей D1.**
> Найдите его в Cloudflare → Storage & databases → D1 → ваша база → Database ID. Это идентификатор, не пароль. Локальный `wrangler.local.toml` менять не нужно.

## Локальный запуск

Node.js **24+** (тесты используют встроенный `node:sqlite`), npm.

```sh
npm ci
npm test
npm run build
npm run worker
```

Открывайте порт 8787 локального Worker. Локальная D1 создаётся в `.wrangler/state`, таблицы и новые колонки — автоматически при запросе. AI отсутствует в локальном конфиге; Cloudflare-токен не нужен. Для HMR оставьте Worker работающим и в другом терминале выполните `npm run dev`: Vite проксирует `/api` на Worker. После изменений серверной схемы перезапуск безопасен; удалять базу не требуется.

В ограниченной облачной среде, где домашний каталог недоступен для записи:

```sh
XDG_CONFIG_HOME=/workspace/.config WRANGLER_SEND_METRICS=false npm run worker
```

Первый вход предлагает 4 экрана знакомства и **явную** кнопку «Посмотреть пример». Демо никогда не синхронизируется. Обычный локальный режим сохраняет реальные изменения в браузере. Перед подключением аккаунта экспортируйте нужные локальные данные: подключение заменяет локальный список серверным. Ключ аккаунта не включается в экспорт.

Для проверки локального синка `POST /api/auth/local` возвращает тестовый ключ. Маршрут работает только при `LOCAL_DEV=true` и hostname localhost/127.0.0.1. Не добавляйте эту переменную в production. Вставьте полученный ключ в настройках двух браузеров. Не используйте локальный тестовый ключ на опубликованном Worker.

## Проверки

```sh
npm test                  # логика + API + Telegram/Notion с node:sqlite и mocks
npm run build
npm run worker            # оставить запущенным для следующих команд
npm run test:browser      # два браузера, офлайн reload, reconnect, удаление
npm run test:visual       # 390/1440 px × светлая/тёмная темы
```

Браузерные тесты используют `/usr/bin/chromium`; другой установленный Chromium задаётся через `CHROMIUM_PATH`. При необходимости установите Chromium средствами ОС либо `npx playwright install chromium` и укажите путь. Скриншоты и отчёт переполнений находятся в `screenshots/`. Тесты запускают все пользовательские экраны; проверяют ошибки JavaScript и горизонтальные переполнения. Скриншоты также проверены визуально. Реальные Telegram/AI/Notion проверяются после деплоя: локальные integration-тесты подменяют внешние API.

## Деплой через Cloudflare Dashboard

1. Поместите этот проект в свой GitHub-репозиторий. В Cloudflare создайте D1 `planner`, скопируйте UUID в **`wrangler.toml`, поле `database_id`**. SQL вручную выполнять не нужно.
2. Workers & Pages → Create → Import repository / Connect to Git → выберите репозиторий и ветку с кодом. Это **Worker**, не Pages. Root directory — корень проекта; build command — `npm ci && npm run build`; deploy command — `npx wrangler deploy`. Для сборки задайте Node 24 (`NODE_VERSION=24`, если это поле доступно).
3. Имя Worker должно совпадать с `name` в `wrangler.toml` (`tiho-planner`), либо измените оба. Конфигурация подключает `DB`, `AI`, статические файлы `dist` и Cron `*/5 * * * *`.
4. В Worker → Settings → Variables and Secrets добавьте **BOT_TOKEN** и **SERVICE_KEY** именно типа **Secret**. BOT_TOKEN выдаёт BotFather. SERVICE_KEY — собственный случайный секрет минимум 32 байта (например, `openssl rand -hex 32`). Не коммитьте секреты, не вставляйте их в `wrangler.toml` и не отправляйте в чат. Для ручного CLI-деплоя альтернативой служат `npx wrangler secret put BOT_TOKEN` / `SERVICE_KEY` и `npm run deploy`.
5. Проверьте `/api/health`: `ok: true`, `ai: true`, `telegram: true`, `local: false`. Первый запрос создаёт/обновляет схему D1. Проверьте наличие Cron в Settings → Triggers.

Приложение использует доступные на Free tier Workers, D1, Workers AI и Cron. Бесплатные квоты конечны: длинное аудио, много пользователей и объём Notion могут превысить лимиты. Приложение не включает платные планы автоматически. Максимум 35 **Notion-запросов** за один запуск Cron; ошибки сохраняют курсор перед неотправленной задачей для следующей попытки.

### BotFather и Telegram

1. Создайте бота командой `/newbot`, сохраните его токен как BOT_TOKEN.
2. В BotFather → Bot Settings → Configure Mini App / Menu Button укажите HTTPS-адрес Worker. Откройте Mini App из своего бота — приложение проверит `initData` и получит персональный ключ.
3. В приложении → Ещё → Настройки → Telegram-бот один раз введите SERVICE_KEY владельца и нажмите «Настроить бота». Ключ используется только для запроса, не сохраняется. Запрос устанавливает webhook, кнопку меню и команды. Требуется персональная авторизация и SERVICE_KEY: обычный пользователь не может перенаправить webhook.
4. Напишите боту `/start`, затем текст или короткое голосовое. Бот работает только в личных чатах. Секрет webhook получается как SHA-256 от `planner-webhook:${BOT_TOKEN}`; приложение рассчитывает его само.
5. В Mini App → Настройки → «Копировать мой ключ». В браузере/PWA вставьте этот ключ один раз. Он даёт полный доступ к вашим данным — храните его как пароль. Смена BOT_TOKEN меняет выдаваемые ключи; после смены откройте Mini App заново и обновите ключи браузеров, повторите настройку webhook.

PWA устанавливается через меню браузера «Установить» / «На экран Домой». В Telegram авто-тема следует Telegram, в обычном браузере — системе. Shell, шрифты и уже загруженные assets кэшируются service worker; API не кэшируется.

### Notion

1. Создайте **internal integration** в Notion, разрешите чтение, добавление и изменение контента.
2. Создайте страницу и через Connections предоставьте интеграции доступ к ней.
3. В планере → Настройки → Notion вставьте integration secret и ссылку на страницу. Будет создана база «Планер» со столбцами Задача, Когда, Готово, Сфера, Минут, Главное.
4. Cron досылает задачи с датой по серверным ревизиям. Удаления и перенос во входящие архивируют связанную страницу; восстановление задачи снимает архив. Изменения в Notion **не** возвращаются в приложение.

Токен Notion хранится только на сервере, зашифрован AES-GCM ключом, полученным из SERVICE_KEY. Смена SERVICE_KEY требует повторного подключения Notion. Повторное подключение создаёт новую базу; старую приложение не удаляет. На ошибке API курсор не перескакивает через неотправленную запись.

## Данные и API

- `tasks` содержит поля из задания, JSON-повтор и checklist; `items` — habit, habit_log, day, note, area, plan, goal, tactic, tactic_log, settings. Ключи таблиц `(user_id, id)`.
- Локальная правка немедленна; push примерно через секунду. Сервер принимает только строго более новый `updated_at`. Равное время оставляет серверную версию. Время клиента дальше 5 минут в будущем отклоняется; исправьте системные часы устройства.
- Каждая принятая запись получает монотонную глобальную `rev` в транзакции D1. Pull хранит **отдельный курсор для каждой таблицы**, выбирает только пользователя, листает по 500 записей. Push возвращает серверную версию для разрешения конфликта. Pull выполняется при фокусе, online и каждые 30 секунд.
- Удаления — надгробия, автоматически не очищаются. Habit log: `hl/<habit-id>:<YYYY-MM-DD>`. Таймеры и ключ авторизации не синхронизируются.
- `Authorization: Bearer <персональный ключ>` либо `X-Service-Key` + `X-Telegram-User-Id` для доверенной автоматизации. SERVICE_KEY даёт административный доступ ко всем пользователям, его нельзя включать в обычные клиентские сборки.
- `GET /api/tasks/sync?since=0`, `POST /api/tasks/sync` с `{ "records": [...] }`; аналогично `/api/items/sync`. Максимум 100 записей на push. Каждой записи нужны `id`, `updated_at`; задаче — `title`, item — `kind`, `data`.

## Принятые решения и границы реализации

- Название — **«Тихо»**. Русский интерфейс, спокойный индиго, жёлтая главная задача, стеклянная навигация, локальные шрифты; строки списков без blur.
- Локальная копия главная для немедленного отображения; при конфликте действует заданный record-level LWW. Слияния отдельных полей нет.
- Обычный планер использует календарь устройства; голос, Cron и Notion — Europe/Moscow. Поля даты/времени текстовые с явным форматом ГГГГ-ММ-ДД / ЧЧ:ММ, поэтому локаль браузера не меняет их вид.
- Пик энергии по умолчанию 10:00; обед 13:00–14:00, перерыв 10 минут. Автоплан сохраняет уже заданные интервалы, сначала располагает главное/глубокое, затем мелочи. Невместившиеся задачи остаются без времени. Отмена доступна в той же шторке до её закрытия.
- Повтор создаёт следующий экземпляр только при выполнении; ежемесячный повтор в коротком месяце использует последний день. Повторный клик не создаёт дубль.
- Неделя и месяц — обзорные списки/сетка без drag-and-drop. Цикл 12 недель — один текущий цикл с целями и шагами по номеру недели, без архива циклов и сложного редактора зависимостей.
- Таймеры показывают оставшееся время по абсолютному deadline, поддерживают параллельный запуск; фоновых системных уведомлений/звукового будильника нет. Напоминания привычек идут через Telegram с точностью Cron (до 5 минут).
- Импорт пропускает совпадающие названия; экспорт месяца содержит задачи выбранного месяца и вспомогательные сущности. Интеграционные секреты и таймеры в экспорт не входят.
- Обработка webhook немедленно подтверждается и продолжается в `waitUntil`. Повтор update_id не создаёт задач-дублей. Если внешняя обработка завершилась ошибкой, бот просит повторить сообщение; отдельной долговечной очереди нет.
- Настройки Notion/Telegram доступны в интерфейсе, но реальные API, квоты AI и доставка сообщений требуют проверки после публикации с вашими секретами.

## Проверить руками после деплоя

- Mini App на iOS/Android: авторизация, авто-тема, экранная клавиатура, безопасные отступы; PWA — установка и повторный запуск без сети.
- Один ключ на телефоне и компьютере: добавление, выполнение, удаление, конфликт офлайн-правок, возврат сети.
- Русское голосовое, несколько задач в сообщении, неправильная дата, сбой AI; отсутствие доступа к чужим данным.
- Привычка с напоминанием на ближайшие 5 минут по Москве; отправка не должна повториться в тот же день.
- Notion: создание, выполнение, правка, удаление, задача без даты; дождаться Cron и проверить ошибки/лимиты Cloudflare в Dashboard.

Проект подготовлен локально. Код не отправлялся в GitHub, production Worker не разворачивался, секреты не создавались.

## Результаты локальной проверки

15 тестов логики/API/интеграций прошли. Отдельный браузерный сценарий проверяет два устройства, офлайн-редактирование, перезагрузку без сети, повторное соединение и распространение удаления. Сборка создаёт precache-манифест всей статики, включая шрифты, поэтому офлайн-старт не зависит от повторного онлайн-посещения. Массовый push разбит на SQL-пакеты с максимум 100 параметрами, а Notion обновляет курсор пакетно для экономии запросов D1. Внешние API в автоматических тестах подменены; production-проверки перечислены выше.

В `screenshots/` сохранены **120 снимков** (30 состояний × 2 ширины × 2 темы), включая онбординг, основные разделы, шторки и нижнюю часть редактора задачи. `screenshots/report.json` содержит результаты проверки переполнений и ошибок браузера. Автоплан также проверен применением и отменой с восстановлением исходного времени задач.
